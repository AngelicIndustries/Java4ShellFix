## Java4ShellFix 1.0.0

- First release. Mitigates CVE-2026-114938 ("Java4Shell"), the OpenJDK AVX-512 VBMI Base64 decode heap overflow, at runtime, with no restart required.
- On startup the mod reports whether this JVM and CPU are exposed, then, if they are, installs a HotSpot compiler directive that keeps the vulnerable `Base64$Decoder.decode0` stub out of optimised code. If the method was already compiled before the mod ran, it discards that code through a self-attach class retransform.
- By default an exposed JVM that could not be mitigated refuses to start, so a vulnerable server fails fast instead of running unprotected. Set `-Djava4shellfix.onFailure=warn` to run anyway. A JVM that is already safe (patched JDK, non-x86, no AVX-512 VBMI, or `-XX:-UseBASE64Intrinsics`/`-XX:UseAVX=2` already set) is never affected.
- One jar runs on Fabric, Quilt, Forge (1.7.10 through 1.21, including lwjgl3ify) and NeoForge. A `-legacy` jar is included for Cleanroom and other hardened FML forks that reject the modern mod metadata.
- The in-memory change is lost on restart. Add `-XX:-UseBASE64Intrinsics` to the JVM startup options, or update to a fixed JDK (17.0.21.1 / 21.0.13.1 / 25.0.5.1 / 27.0.1.1 or later), to stay protected.
- The runtime mitigation technique is reimplemented from, and credited to, Theori/Xint's [runtime patch for this CVE](https://github.com/theori-io/java4shell-runtime-patch-CVE-2026-114938).
